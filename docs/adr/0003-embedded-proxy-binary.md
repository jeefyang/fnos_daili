# ADR 0003：每个代理包内嵌同一份通用反代二进制

- 状态：accepted
- 日期：2026-11-16
- 相关：T1 #7、T2 #4

## 背景

代理应用需要在没有托管台的情况下独立运行。可选做法：

1. 每个包内嵌同一份通用二进制，配置烤进 `config.json`；
2. 包内只放配置，运行时调用托管台的常驻二进制；
3. 按目标编译专用二进制。

方案 2 会让代理的生死依赖托管台：托管台卸载/升级/挪目录，所有代理入口一起坏。方案 3 在 NAS 上编译慢、产物不可复现，且每个目标逻辑其实相同。

## 决策

每个代理 fpk 的 `app/bin/proxy` 是同一份通用反代二进制；生成时把 `mode`、`target`、TLS/guard/auth/timeouts 烤进 `app/config.json`。安装后 `cmd/main` 把它复制到 `TRIM_PKGVAR/config.json`（0600），运行时只读这份配置。

## 后果

- 单包多约 10–15MB；包自包含，托管台卸载/升级不影响已装代理。
- 代理逻辑升级 = 重新生成 + 重装每个应用；没有“共享二进制热升级”。
- 构建按架构出包：v1 先 x86/amd64；ARM 另编，不写 `platform=all`。
- 配置是唯一事实源；改任何字段都要重新生成，不能改安装目录里的文件。

## 被否方案

- **共享托管台二进制**：卸载即全挂，升级要协调所有应用。
- **按目标编译**：NAS 上构建慢、不可复现，且没有目标专属逻辑。
